00 · Overview

What this system does

Multiple dummy users log in by email, each pre-authorized for one or two companies' earnings-call transcripts. Every user can search and chat over the documents — but only the ones they're cleared for, enforced at the database query itself, and each user's conversation history is fully isolated from every other user's.

The assignment this implements

  • Dataset: 4–5 companies' earnings-call PDFs (data/*.pdf — TCS, Infosys, Axis, HDFC, Tata Technologies).
  • Per-user access control: each dummy email is scoped to one or two companies; query results must never leak unauthorized documents.
  • Conversational Q&A: follow-ups use prior turns as context, scoped per user/session so concurrent users never cross-talk.
  • A basic UI: email-picker login, submit a query, view an answer, ask follow-ups.
  • Must support multiple simultaneous users without state leaking between them.

The core design decision

Enforcement point Access control lives in the retrieval query itself — MongoDB Atlas's $vectorSearch pre-filters candidate chunks by company_id before ranking, using a company list re-derived fresh from the JWT owner's email on every request. It is never a post-filter over unfiltered results, and never trusts a client-supplied company list.
01 · Architecture

Two pipelines, one store

An offline ingestion pipeline turns PDFs into embedded, access-tagged chunks in MongoDB Atlas. An online serving pipeline answers user questions by searching only the chunks that user is cleared for.

02 · Ingestion pipeline

PDF to searchable vector

Three scripts, run in order, each reading the previous one's output directory. All three are run from the repo root with PYTHONPATH=backend (see §12).

01

parser.py — data/*.pdf → data/parsed/*.json

Converts each PDF to markdown with Docling (DocumentConverter), then extract_metadata() derives a company and fiscal period — first from the filename (e.g. TCS_Q4FY24.pdf), falling back to regex patterns over the first ~3–5k characters of extracted text (a "... Limited/Ltd/Inc/Corporation/Bank" suffix for company name; Q1FY24/FY2024-25/date-style patterns for period). Output: {"metadata": {...}, "text": "..."} per file.

02

chunker.py — data/parsed/*.json → data/chunks/*.json

Splits each transcript into speaker-turn chunks, not fixed-size windows — the natural unit of an earnings call:

  • Splits the transcript into prepared_remarks / qa sections at a "Q&A session" marker.
  • Finds "valid" speakers — names that recur ≥ 2 times (MIN_SPEAKER_OCCURRENCES) — to filter out false positives like letter salutations.
  • Splits each section into (speaker, text) turns at those speaker markers; classifies each speaker as moderator / management / analyst, using a parsed "MANAGEMENT:"/"CORPORATE PARTICIPANTS:" header block where present.
  • Long turns are further split at word boundaries, capped at MAX_CHUNK_CHARS = 1500 characters.
  • Q&A turns get a shared qa_pair_id linking an analyst's question to the management reply that follows it.

IDs: company_id = slugified company name; doc_id = {company_id}_{quarter}_{year}; chunk_id = {doc_id}_{section_type}_{NNN} — e.g. TCS_Q4_2026_qa_019.

03

embed_and_store.py — data/chunks/*.json → MongoDB Atlas

Embedder calls the OpenRouter embeddings API directly over HTTP (via requests, not a local model) — default model nvidia/nemotron-3-embed-1b:free, batched 32 texts per call. Each chunk's text is embedded and upsert-ed into MongoDB keyed by chunk_id as _id, with every other chunker field stored alongside the embedding vector. On first run, ensure_vector_index() creates the Atlas $vectorSearch index and polls (up to 120s) until Atlas reports it queryable.

Vector store note The project fully migrated off Chroma to MongoDB Atlas. vector_db/ (a legacy Chroma persistence directory) is stale and unused by any current code path.

04 · Access control

Scoped at the database query, not the UI

Enforced Here This is the assignment's central requirement, and the whole design routes through one mechanism to satisfy it.

The user map

backend/src/config/users.py hardcodes a dummy directory — DUMMY_USERS: dict[str, list[str]]: 

DUMMY_USERS = {
    "alice@example.com": ["TCS", "Infosys"],
    "bob@example.com":   ["Axis"],
    "carol@example.com": ["Hdfc"],
    "dave@example.com":  ["TataTechnologies"],
    "eve@example.com":   ["TCS", "Hdfc"],
}

Login → JWT

POST /api/auth/login looks up the email, and if known, issues a JWT (security.py::create_access_token) whose payload embeds sub (email), companies, and an expiry (access_token_expire_minutes, default 60). Unknown emails get a 401.

Two different levels of trust in that token

EndpointCompany sourceWhy
POST /api/query Trusts the JWT's cached companies claim directly Simple, single-shot retrieval endpoint
POST /api/conversations/{id}/messages Re-derives companies via a fresh get_user_companies(email) lookup, ignoring the JWT's cached claim A still-valid token issued before a permission change can't leak access to a company since revoked

Enforced inside the vector search itself

The Atlas Search index on transcript_chunks declares company_id as a filter field. Every $vectorSearch call passes filter={"company_id": {"$in": allowed_companies}} as part of the ANN stage — unauthorized chunks are excluded from the similarity search itself, never fetched, never ranked, never returned. If allowed_companies is empty, retrieval short-circuits to [] (deny-by-default) rather than searching unfiltered. 

sequenceDiagram
  participant U as Browser
  participant Auth as POST /api/auth/login
  participant Chat as POST /conversations/{id}/messages
  participant Users as config/users.py
  participant Mongo as Atlas $vectorSearch

  U->>Auth: { email }
  Auth->>Users: get_user_companies(email)
  Auth-->>U: JWT { sub: email, companies, exp }

  U->>Chat: Bearer JWT + question
  Chat->>Chat: decode JWT → email only
  Chat->>Users: get_user_companies(email)  (fresh, not cached)
  Chat->>Mongo: filter company_id in [fresh companies]
  Mongo-->>Chat: only chunks caller is authorized for
  Chat-->>U: answer + citations

The chat endpoint never trusts the JWT's cached company list for access control — only for identity.

Not a security control The LangGraph classify node (greet / deny / continue) is UX routing only. It never decides which companies a question may touch — that's the retrieval filter's job, deterministically, every time.
05 · Retrieval layer

Query → vector → filtered ANN search

retriever.py

retrieve(query, allowed_companies, top_k, embedder) is the single entry point used by both the raw-query endpoint and the chat graph's fetch node. It embeds the query text (Embedder.embed_query) and delegates to mongo_store.vector_search. Returns [] immediately if allowed_companies is empty — it never issues an unfiltered search.

mongo_store.vector_search — the actual pipeline

[
  {"$vectorSearch": {
      "index": "chunk_vector_index",
      "path": "embedding",
      "queryVector": query_vector,
      "numCandidates": 100,
      "limit": top_k,
      "filter": {"company_id": {"$in": allowed_companies}}
  }},
  {"$project": {
      "embedding": 0,
      "score": {"$meta": "vectorSearchScore"}
  }}
]

The vector index itself is created by ensure_vector_index(): a vector field on embedding (cosine similarity) plus a filter field on company_id — the filter field is what lets Atlas apply company_id restriction during the ANN search, not as a second pass.

06 · Conversational RAG

The LangGraph pipeline

POST /api/conversations/{conv_id}/messages routes every message through a five/six-node graph (src/graph/graph.py), compiled once and cached (lru_cache). 

flowchart TD
  START(["START"]) --> classify
  classify -->|"greet / deny"| canned["canned_response"]
  classify -->|"continue"| rephrase
  rephrase --> fetch
  fetch --> build_answer
  build_answer --> guardrail
  canned --> END(["END"])
  guardrail --> END
NodeWhat it does
classify LLM call, temperature 0, classifier prompt → {"route": "greet"|"deny"|"continue"}. On any failure, defaults to "continue" rather than blocking the pipeline.
canned_response Greeting or scope-refusal text, no retrieval or generation cost incurred.
rephrase If there's prior history, rewrites a follow-up ("and their margins?") into a standalone question using the rephraser prompt + turn history. Falls back to the raw question on failure or if history is empty.
fetch Calls retrieve() with the standalone question, state.allowed_companies, and chat_top_k (default 6). This is the one deterministic ACL checkpoint in the graph.
build_answer Formats retrieved chunks as labeled context ([chunk_id] (company, quarter year, speaker): text), calls the chat model at chat_temperature (default 0.1) with the answer prompt. Citations are the chunks whose chunk_id literally appears in the generated text, falling back to the top 3 if none matched.
guardrail A second LLM call re-checks the answer against the same context for grounded (no fabricated facts) and safe (stays in scope, ignores injected instructions). If either is false, the answer is replaced with a generic fallback and citations are cleared. Fails open on an LLM/network error — see below.
Fail-open, by design If the guardrail call itself throws (timeout, malformed JSON, etc.), the node returns the original answer as final rather than blocking. This is safe specifically because the guardrail checks answer quality, not access control — the ACL boundary in fetch already ran and can't be bypassed by a guardrail hiccup.

Shared state (ChatState, a TypedDict)

Threaded through every node: email, allowed_companies, conv_id, question, history are set once before graph.invoke(); each node adds its own keys (route, standalone_question, chunks, answer/citations, guardrail_passed/final_answer).

07 · Prompts

Versioned, file-based, swappable without a code change

Each prompt lives at prompts/<name>/vN.txt; prompts/registry.py::CURRENT_VERSIONS pins which version is served. Rolling a prompt forward means adding a new vN.txt and bumping the pointer — old versions stay on disk for rollback or A/B comparison, and load_prompt(name, version) lets a caller request an explicit version.

PromptPinnedCore instruction
classifierv1Route only — greet / deny / continue; explicitly told access control is not its job.
rephraserv1Rewrite a follow-up into a standalone question; never answer it.
answerv1Answer strictly from provided context; inline-cite every claim with [chunk_id]; say plainly when context is insufficient; never speculate about companies absent from context.
guardrailv1Verify grounded (no fabricated facts) and safe (in scope, ignores injected instructions) as strict JSON.
08 · Conversation history

Isolation by construction, not by query filter

store/history_store.py keys every conversation document's _id as f"{user_email}::{conv_id}" in a MongoDB collection (conversations by default).

  • Two different users' conversation documents can never collide, even on a guessed or reused conv_id — the compound key addresses an entirely different document.
  • get_full_thread(email, conv_id) additionally double-checks the returned document's user_email matches — a defense-in-depth line against IDOR that holds even if the ID scheme ever changes.
  • Every route resolves the owning user from the decoded JWT (get_current_user), never from a request body or path param.
  • Turns are capped to the most recent history_max_turns (default 6) when loaded for the rephraser/answer context — {"turns": {"$slice": -limit}}.

12 · Running the system

Setup, and the import-path gotcha

Read this before running anything The codebase mixes two import styles in one process: api/main.py and api/routes/*.py use relative imports (from ..config...) — they must be imported as part of the backend.src.* package, i.e. run from the repo root. retrieval/, ingest/, store/, graph/, and llm/ use absolute imports (from src.config...) — they only resolve if backend/ itself is on sys.path. The combination that satisfies both: run from the repo root with PYTHONPATH=backend. The Docker image bakes this in.

1 · MongoDB Atlas

$vectorSearch requires real Atlas (a free M0 tier works) or the mongodb/mongodb-atlas-local Docker image — plain community MongoDB has no vector search. Create a cluster, copy the mongodb+srv:// connection string, and allow your IP under Network Access.

Docker (full stack)

docker-compose.yml runs mongodb (Atlas-local image), backend, and frontend. The backend's MONGO_DB_STRING is overridden in-compose to the in-network mongodb service. Containers don't run ingestion automatically: 

docker compose up --build
docker compose exec backend python -m src.ingest.parser
docker compose exec backend python -m src.ingest.chunker
docker compose exec backend python -m src.ingest.embed_and_store

API at localhost:8000, frontend at localhost:5173.

13 · Testing

Offline, stubbed, graph-level

tests/ runs with plain pytest from the repo root — no OPENROUTER_API_KEY or MongoDB needed, since conftest.py puts backend/ on sys.path itself.

  • test_graph_routing.py — monkeypatches chat_completion and retrieve to exercise the real LangGraph wiring: greet/deny short-circuit before retrieval, a grounded continue produces citations, and an ungrounded guardrail verdict replaces the answer and clears citations.
  • test_prompts.py — every prompt pinned in CURRENT_VERSIONS loads and is non-empty; an explicit version matches the pinned default; unknown name/version raise the right exceptions.
14 · Known gaps & notes

Things to know before extending this

  • Legacy Chroma directory. vector_db/ is unused — the project migrated fully to MongoDB Atlas; don't read from or write to it.
  • HF_TOKEN is a leftover. An earlier version of Embedder used a local sentence-transformers model; embedding now goes entirely through the OpenRouter API, so HF_TOKEN is no longer read anywhere.
  • Demo user list duplication. frontend/src/screens/Login/demoUsers.ts mirrors backend/src/config/users.py for display purposes only — keep both in sync manually if the user map changes; access control itself never depends on the frontend copy.
  • /api/query vs. the chat endpoint. The raw retrieval endpoint returns ranked chunks with no LLM synthesis and trusts the JWT's cached company claim directly; the conversational endpoint is the one with the freshly re-derived permission check and full pipeline.
  • Ingest scripts default to repo-root-relative paths. --data-dir/--chunks-dir/--parsed-dir default to data/..., which only resolves when the current working directory is the repo root — not backend/.
